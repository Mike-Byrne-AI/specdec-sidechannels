# Findings

Running log of empirical findings. Append-only. New findings get IDs (`F<N>`) that can be cited from code, decisions, task packs, and other findings.

## Format

```markdown
### F-N — <short title>

**Observation**: <what was measured, 1-3 sentences>
**Context**: <which run, what config, what split>
**Why it matters**: <the implication — what this rules in or out>
**Status**: <acted on (link) | queued (link) | noted>
**Open question**: <what we still don't know>
```

## Rules

- **Append-only.** Never edit an existing finding. If invalidated, write a new finding documenting the invalidation.
- **Numbered.** Pick the next free F-N. Numbers are permanent and citable.
- **Empirical.** A finding cites a run number, a measurement, or a concrete observation. If it doesn't, it's not a finding — it might be a decision (`trellis-docs/trellis-decisions.md`) or a hypothesis (a task pack).
- **Useful.** A finding earns its slot if a future session would make a different choice because of it. Otherwise it's noise.

## Findings

### F-1 — Pure-integer v0 pipeline round-trips bit-exactly, with expected ratio profile

**Observation**: 30/30 unittest cases pass, including 80 seeded coder fuzz cases (varied alphabets 2–40 symbols, changing CDFs) and 6 conformance vectors. Measured adaptive-order1 ratios: 1.87x on English markdown (4,394 B prose), 3.63x on repetitive ASCII, 0.93x (expansion) on incompressible DRBG bytes. Pure-Python throughput ~32 KiB/s encode, ~30 KiB/s decode; 8 KiB random round-trip 0.52 s.
**Context**: run_002, this repo at v0.1.0, CPython 3.12.3 Linux x86_64 (envprobe digest in run row), stdlib only.
**Why it matters**: The trust base (integer coder + container + vectors) is real and testable before any model work; the expansion case confirms honest behavior on incompressible input; throughput number sets the baseline E-005 must beat.
**Status**: acted on (conformance/vectors_v0.json frozen; TP-1 unblocked).
**Open question**: Does an independent machine reproduce the vector hashes byte-exactly? (First external check = the operator's own box.)

### F-2 — Integer probability grid absorbs sub-half-step drift; diverges past a step (the drift-sponge mechanism works)

**Observation**: On 200 seeded 128-symbol distributions at grid total 2^15 (step ≈ 3.06e-05 in probability space): alternating ±1e-11 perturbations produced identical quantized CDFs in 200/200 cases; ±1e-3 perturbations produced differing CDFs in 200/200 cases.
**Context**: run_002, quantize_probs largest-remainder rule per specs/decode-profile-v0.md, tests_project/test_cdf.py drift test.
**Why it matters**: Direct evidence for the architecture's central mechanism (docs/04): quantization is a real drift sponge with a measurable boundary near half a grid step. Sizes the question E-001 must answer — is real cross-GPU drift below that boundary?
**Status**: queued (E-001/E-002 measure real drift against this boundary; TP-2 builds the safeguard for what the grid can't absorb).
**Open question**: Where exactly between 1e-11 and 1e-3 does absorption break on real logit distributions (not synthetic uniform-random weights), and how does vocab size shift it?

### F-3 — Untrusted-input review: coder is sound, container skin was not (now hardened)

**Observation**: Adversarial pass on the v0 container. The coder/model core is robust — a sampled single-byte mutation sweep over a 636 B container produced only clean ContainerError (0 silent successes, 0 leaked exceptions); exhaustive short-input round-trips (every length 0–64 x3 seeds, all 256 single bytes, 5000x-repeat rescale path, alternating 0/255) all bit-exact; three-interpreter cross-process pack was byte-identical. But the manifest parser leaked bare KeyError/TypeError/AttributeError on 5 of 7 hand-crafted manifests, accepted a negative original.size as a SILENT SUCCESS, and an attacker-chosen original.size of 10^12 drove unbounded decode work (decompression bomb). Also measured: fixed manifest overhead floor ~457 B per container.
**Context**: review session on v0.1.0; new module src/lockstep/manifest.py + tests_project/test_manifest.py added in response; suite 30 -> 42 tests, all green; all Trellis gates pass.
**Why it matters**: A format whose entire promise is "loud, well-typed failure, never silent corruption or surprise cost" cannot leak builtins, cannot silently accept malformed size, and cannot let a 600 B file request a terabyte of work. The core was trustworthy; the front door was not. Post-fix: 0 leaked exceptions, negative size refused, bomb refused instantly via a caller-tunable max_original_size ceiling (default 8 GiB).
**Status**: acted on (strict validate_manifest is now the single reader choke point; unpack/read_manifest take max_original_size; D-11 records the posture).
**Open question**: The ~457 B manifest floor makes small archives inefficient — is a compact binary-header profile (OQ-11) worth it, or is "archival = large inputs" a sufficient answer? And should there be a streaming size-bomb guard that also bounds DECODED bytes as they are produced, not just the declared size (belt and suspenders for chunked mode, TP-3)?

### F-4 — First-cut cost model: under placeholder economics, LLM-archival loses to zstd -19 in every scenario, and compute cost dominates

**Observation**: tools/lockstep_costmodel.py, run on three built-in scenarios (compliance cold 1TB/84mo/2 reads; e-discovery warm 200GB/24mo/500 reads; research steward 5TB/120mo/50 reads) with placeholder-but-plausible lsp1 numbers (6x ratio, 0.5 MB/s pack, 2 MB/s decode, $2.50/GPU-hr): zstd -19 wins all three by 1–2 orders of magnitude, and pack/decode COMPUTE cost dominates so heavily there is no read-frequency crossover — e.g. cold archive TCO $148 (zstd) vs $2,169 (lsp1), of which $1,389 is pack GPU-hours against only $56 of storage.
**Context**: review session; model inputs are PLACEHOLDERS (docstring says so); throughput must come from a real run (Blueprint B / tools/lockstep_bench.py) before any verdict is trusted. [withheld: Blueprint B not in this repository; see WITHHELD.md]
**Why it matters**: This is docs/08 killer #1 made concrete on day one. It does NOT kill the project, but it sharply constrains where the thesis can survive: only regimes where (a) packing is amortized to near-zero (pack once, essentially never re-pack) AND decode is rare/cheap, or (b) the value is reframed from cost-savings to provable restorability (Blueprint E receipts), or (c) batch pack economics are radically better than $/GPU-hr suggests. The compute-for-storage trade, priced naively, is underwater. [withheld: Blueprint E not in this repository; see WITHHELD.md]
**Status**: acted on (cost model committed as a standing tool; steers next work toward measuring real throughput and finding the survivable regime, not building more format features).
**Open question**: Is there ANY realistic (corpus size, read frequency, model size, pack amortization) point where lsp1 wins on cost with margin? Feed measured pack/decode throughput from a real small-model run and sweep. If none exists, the project pivots to the restorability framing or the provenance spin-off (Blueprint D) — and that is a decision-grade finding, cheaply bought. [withheld: Blueprint D not in this repository; see WITHHELD.md]

### F-5 — The coder's TOTAL_MAX=2^16 structurally forbids LLM vocabularies; the constant is conservative, not load-bearing

**Observation**: `quantize_weights` requires total >= V and `Cdf` rejects total > TOTAL_MAX (2^16). Measured: Llama-3 (128,256), Qwen2-ish (151,936) and Gemma-ish (256,128) vocabularies raise CoderError and cannot build a CDF at all; Mistral's 32,768 "fits" with **2.0 units/symbol and 50.0% of probability mass consumed by the mandatory >=1 floor**, costing **0.999 excess bits/token against a 3.03-bit distribution (~33% ratio loss)**. Separately verified the ceiling is arbitrary: the WNC renormalization invariant keeps range > QUARTER = 2^30, and the coder round-trips correctly at totals 2^16, 2^20, 2^24, 2^28 and 2^30 with CODE_BITS=32 — PROB_BITS_MAX is conservative by 14 bits.
**Context**: run_004 synthesis session; no new hardware; derived by crossing F-1/F-2 (measured on the 256-symbol byte alphabet at grid 2^15) against TP-1's plan to drive the same coder with an LLM vocabulary.
**Why it matters**: TP-1 is unbuildable as written — not slow, not lossy, impossible. The v0 trust base contains a constant that forbids the exact thing the project exists to do, and neither F-1, F-2, nor the specs noticed because every measurement to date used a 256-symbol alphabet. The fix is cheap (raise PROB_BITS_MAX; lsp1 likely wants CODE_BITS=64 for headroom) but is a format break under D-9 — cheap today, expensive once any third party holds a vector file.
**Status**: acted on (D-12 records the constants posture; TP-1/TP-2 marked BLOCKED; tools/lockstep_profile_advisor.py added so a command catches this class of error).
**Open question**: For lsp1, is raising PROB_BITS_MAX to ~27 within CODE_BITS=32 (3 bits of headroom) acceptable, or does the profile want CODE_BITS=64 outright — and what does 64-bit cost a future C/Rust port on 32-bit-friendly targets?

### F-6 — The drift sponge does not scale: at LLM vocab, no grid both absorbs drift and preserves ratio

**Observation**: Re-ran F-2's exact methodology at LLM scale with PA-3's drift class (eps=1e-7). At V=32,768/T=2^15 the CDF was identical under drift 24/24 — but at **394% excess entropy** (11.97 excess bits vs 3.03 true), i.e. it "absorbs" only because coarse quantization already destroyed the distribution. Every configuration preserving ratio (V=32,768 @ 2^20: 1.5% loss; V=128,256 @ 2^24: 0.4% loss) desynced **0/24 identical — every token**. Ratio needs T >= 2^24 at LLM vocab; absorbing 1e-7 drift needs T << 2^23. The windows do not overlap.
**Context**: run_004 synthesis session, peaky(tau=3) and zipf(1.0) synthetic distributions, TOTAL_MAX patched to 2^30 to make the test possible at all (see F-5).
**Why it matters**: F-2's central mechanism — the architecture's headline in docs/04 — was an artifact of the 128-symbol regime it was measured in. At lsp1 scale the probability-space grid cannot work, so D-8's safeguard side-stream would fire on ~100% of tokens (transmitting the model's decisions, defeating the purpose) and E-004's 10% overhead stop condition trips immediately. **OQ-4 is answered by elimination: the grid cannot live in probability space.**
**Status**: acted on (D-13 moves the grid to logit space + top-k; OQ-4 closed; E-002/E-004 re-scoped; F-7 supplies the replacement mechanism).
**Open question**: Does real LLM logit drift actually sit at PA-3's ~1e-7, and is it uniform across positions/magnitudes? Every number above is keyed to that assumption — E-006 must measure it on real hardware before the lsp1 profile freezes.

### F-7 — Logit-space quantization with top-k truncation restores sparse corrections; rate obeys k*eps/delta

**Observation**: Moving quantization from probability space (a global function of all V logits) to **logit space with top-k truncation** collapses the drift surface from V to k. Measured correction rate against theory (fresh continuous logits per trial, V=4096, k=64, eps=1e-7): delta=1e-3 -> **0.67% measured vs 0.64% predicted**; delta=1e-4 -> 5.13% vs 6.40%; delta=1e-2 -> 0/1500 vs 0.06% predicted. Top-k truncation is nearly free on peaky distributions (tail mass beyond top-64 ~1e-9).
**Context**: run_004 synthesis session, synthetic continuous logits. TWO earlier probes were discarded as invalid: (a) synthetic jitter on a decimal grid aligned with the coarse logit step, producing a spurious "coarser is worse" inversion; (b) a trial loop resampling perturbation signs but not base logits, producing a spurious 0% at every step. Both agreed with no theory, which is how they were caught.
**Why it matters**: This is the constructive exit from F-6's squeeze and converges independently on PA-3's proposal. It gives lsp1 a buildable shape (coarse logit grid + top-k + exact integer apportionment over k+1 symbols) and a design law that sizes the safeguard stream before any GPU is rented: correction_rate ~ k*eps/delta.
**Status**: acted on (D-13; encoded in tools/lockstep_profile_advisor.py; E-006 will validate on real logits).
**Open question**: Does the law hold on real logit distributions, where near-boundary logits may be correlated across positions rather than independent? Correlation would make corrections bursty rather than Poisson, which changes the side-stream's framing, not its size.

### F-8 — Packing is 92% of TCO and needs a ~100x miracle; the thesis survives only as a byproduct of inference already being run

**Observation**: F-4's cost model priced lsp1 decode at GPU rates, contradicting D-10 (CPU-first decode). Re-priced (1 TB, 84 mo, 2 reads): lsp1 TCO $1,502.67 vs zstd -19 $148.41, of which **pack is $1,388.89 = 92% of all cost**. Break-even requires **20.1 MB/s pack ≈ 5M tokens/sec on one GPU** against ~10–50k tok/s realistic — a **100–500x gap**. Hybrid chunk-routing (LLM only on text-like chunks, from F-1's 0.93x expansion on incompressible bytes) improves cost ~5x but loses at every text fraction (20% text -> $441; 5% text -> $242). Ratio is nearly free: 15% ratio loss ~ 0.5% of TCO. **With pack cost set to zero, lsp1 wins by 23% ($113.78 vs $148.41).**
**Context**: run_004 synthesis session; placeholder throughput/pricing inputs unchanged from F-4 (still unmeasured — see docs/08 and Blueprint B). [withheld: Blueprint B not in this repository; see WITHHELD.md]
**Why it matters**: Three sessions of engineering levers (grid, ratio, hybrid routing, CPU decode) move a term worth ~8% of cost while the dominant 92% went unmeasured and unattacked. No experiment in the portfolio measures pack throughput or amortization (EF-6). The only economic shape where the thesis survives is a corpus whose logits are already being computed for another purpose — RAG ingestion, embedding, indexing, curation, moderation — which reframes the product from "a compressor you buy" to "a byproduct you harvest", and reframes the first customer conversation entirely.
**Status**: queued (D-14 records the positioning bet as unvalidated; the next unit of work is a conversation with a prospective user, not more format code).
**Open question**: Is there a real population running full-corpus inference AND retaining that corpus long enough for archival economics to matter — and would they accept a pack-time coupling to a pinned model version? If not, the cost thesis is dead everywhere and only the attestation framing (docs/07 Blueprint E) survives. [withheld: Blueprint E, docs/07 not in this repository; see WITHHELD.md]
**Dated note (2026-10-18)**: the figures in this Observation rest on the cost model's placeholder inputs, the 2 MB/s decode rate among them (docs/audits/2026-10-18-image-audit/README.md, item B3). With any decode rate the record measured in that placeholder's place, lsp1 costs more than zstd -19 even with packing free, so the free-packing branch ("wins by 23%") does not survive measured inputs; the verdict that the standalone thesis loses survives every input set the audit's refuters tried, and the reason given for it, the 92% share, does not. The Observation stands as written.

### F-9 — The manifest claimed full model pinning while the reader ignored three semantic fields

**Observation**: Starting from the reviewed/synthesis archives, independently forging `profile.model.alphabet`, `profile.model.increment`, or `profile.model.rescale_limit` left the archive acceptable and decodable; all three values were parsed but never compared with the selected model. The supplied 42-test product suite remained green for every forgery.
**Context**: run_005 unification review of the three supplied repositories; each field was modified in an otherwise valid, re-framed container so payload and original hashes remained valid.
**Why it matters**: A decoder contract that records but does not enforce state-transition parameters is not model-pinned. Another implementation could honor the forged value and diverge while this reader silently uses its compiled default, defeating the format's central determinism claim.
**Status**: acted on (`validate_manifest` now requires the complete exact registered model profile, public profile tables are immutable, and adversarial regressions cover every field without changing any lsp0 vector).
**Open question**: Before lsp1 freezes, should the profile use an explicit schema identifier plus a full parameter object, or content-address the complete transition specification to make omissions mechanically harder?

### F-12 — First E-006 evidence (via amber, TinyLlama-1.1B, RTX 3080 Ti): fp32 cross-device logit drift eps~3e-6 median / 1.3e-4 max; the k*eps/delta law holds; a delta=1e-3, k=64 grid crosses at 22% of positions even at fp32, and at 100% under bf16/fp16 — while token RANK order stayed exactly stable at fp32

**Observation**: Amber's Phase 2 census (amber F-5/F-6; `amber/results/p2_e006_grid_crossing.json`) dumped top-64 logits of TinyLlama-1.1B-Chat over 49,152 teacher-forced positions on CPU fp32 and on a 3080 Ti under fp32/bf16/fp16/int8/nf4. CPU-vs-GPU fp32: |delta logit| p50 3e-6, p99 1.5e-5, max 1.3e-4 (logits of magnitude ~10). Positions with at least one top-64 grid crossing: delta=1e-2 -> 2.6%; delta=1e-3 -> 21.9%; delta=1e-4 -> 90.8%. F-7's law k*eps/delta with the measured median eps predicts 1.9% / 19% / saturated. bf16 and fp16 vs CPU fp32 cross at 100% of positions for every delta (eps p50 0.024 / 0.003). The same dumps show top-1 RANK flips of 0 (fp32), 0.11% (fp16), 1.0% (bf16), every flip attributable to a near-tie; run-to-run on either device was bit-identical; fp32 batch 1 vs 8 differed by <=1.9e-4 with 0 rank flips.
**Context**: run_007 (amber's capture, this repo's protocol); one CPU/GPU pair, one GPU architecture, one model; torch 2.6.0+cu124, cudnn autotune defaults; not the >=2-architecture census E-006 asks for.
**Why it matters**: The single number lsp1 rests on (E-006) now has a first value, and it is worse than PA-3's ~1e-7 assumption by 1.5-3 orders of magnitude on this pair: D-13's default profile (delta ~1e-3, k ~64) would need a safeguard correction at ~22% of positions on fp32 cross-device decode, and bf16 decode is off the table for a grid contract entirely. delta=1e-2 restores sparsity (2.6%) at a ratio cost E-002 must price. The law itself is confirmed on real logits, so the profile can be sized from a measured eps rather than argued. Separately, amber's weaker ORDER contract costs nothing at fp32 on the same data — the D-15 split (rank codec for token streams; grid + safeguard only where exact probabilities are required) is now evidence-backed rather than argued.
**Status**: queued (E-006 remains open for cross-architecture and burstiness; D-13's delta default should be revisited against this eps before TP-2 is unblocked).
**Open question**: Is eps on an A100/H100 pair (PA-7's failing case) near this 3e-6 median, or is the CPU-vs-consumer-GPU pair unusually far apart? And does the crossing burstiness (not computed here) make the safeguard a run-length stream?

### F-13 — Second E-006 datapoint (Llama-3.2-1B-Instruct, V=128k): fp32 cross-device eps p50 7e-6 / max 4.5e-4; delta=1e-3 grid crosses at 41% of positions at fp32 (law predicts 45%), delta=1e-2 at 5%; rank order stable to 1 flip in 49k

### F-14 — First measured pack-side throughputs for the byproduct regime (amber Phase 1, 3080 Ti): target generation 33 tok/s (3B bf16, batch 1, KV), draft rank scoring 9.2k tok/s (1B bf16); the archive itself costs 0.47 bits/token on target-generated text

### F-15 — Rank-ORDER stability has a depth: on the Llama-3.2-1B dumps an fp32 decoder reproduces an fp32 encoder's token order exactly to rank 64 (0 desyncs / 49k positions), while bf16 mis-orders 3% of rank-2 and 9-26% of rank-3..8 tokens and a top-1 near-tie escape cannot buy that back; lockstep.rac is now amber's production coder (value-free contexts) and gains only 1% over Elias-gamma there

**Observation**: amber F-10 (`amber/results/p2b_escape_robustness.json`, run_008's dumps re-read at top-256): symbol streams built under cpu_fp32 and resolved under each GPU arm. cuda_fp32_b1: 1 desync at theta=0 (gap 1.3e-5), 0 at any escape margin, across all ranks to 64. cuda_fp16: 5.1% of rank-2..64 corrections mis-resolve (rank 2 0.4%, rank 8 3.7%, ranks 17-64 14%). cuda_bf16 (b1 or b8): 23-26% (rank 2 2-3%, rank 3 7-9%, rank 8 20-26%, 17-64 60%). Top-1 escapes remove every A-desync at theta >= 2(tau_enc+tau_dec) — no wide-gap flip anywhere (XB-3 clean). amber F-9: lockstep.rac with contexts restricted to coded-symbol history gives 0.417 vs gamma 0.421 bits/token on held-out target-generated text; value-derived contexts would give 0.321 and are forbidden there (grid-crossing hazard, this repo's F-6/F-7/F-12/F-13).
**Context**: run_010; one model, one box, teacher-forced text (deeper ranks than target-generated text; per-rank rates transfer, the mix does not); cross-architecture still pending. amber wrote its own small-alphabet adaptive model because `models.AdaptiveByteModel` hard-codes a 256-symbol alphabet.
**Why it matters**: E-006 asked how expensive rank stability is; F-12/F-13 answered for top-1 only. The answer has a depth axis: the fp32 contract is free at every depth a rank codec uses, and NO reduced-precision contract is rescuable by top-1 escapes because the exposure sits at ranks 2..8 where logit density is high. For lockstep this sharpens the product: a dtype pin (fp32 replay, ~3.65x bf16 time on this GPU) is the whole determinism ask for rank-coded archives — cheaper than any lsp1 grid and cheaper than bitwise determinism. The coder result is the first production use of rac: correct, byte-exact, and NOT the lever (stateless gamma ties it on short streams), which bounds the value of coder work in this repo.
