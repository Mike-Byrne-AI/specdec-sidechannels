# Decisions

## D-1 — Import sideband's tested primitives; never re-implement
- date: 2026-08-28, status: adopted
- The world, distributions, and (later, for sampling-mode archives) the
  verifier math come from the sideband package as a dependency. Mirror of
  sideband D-3. Install the sibling repo first: pip install -e ../sideband.

## D-2 — Decoder-reproducibility constraint
- date: 2026-08-28, status: adopted (load-bearing)
- Everything that shapes the code — the draft distribution, its stable
  ordering, any steering — must be a function of DECODER-AVAILABLE state:
  header, decoded prefix, explicit hint bits. Encoder-only signals (the
  target's p) may decide what to correct or what hints to spend bits on, but
  may never silently reshape q: a p-steered q at encode time is undecodable
  by a draft-only decoder. Corollary: serve-time steered spec-decode traces
  are NOT automatically archives; archive-compatible serving modes trade
  some steering speedup for decodability (BLUEPRINT "serving compatibility").

## D-3 — Regime split: A (model-generated, deterministic) is the flagship
- date: 2026-08-28, status: adopted
- Regime A: content generated by the target under deterministic decode;
  archive = divergence corrections against deterministic draft replay; the
  target is not needed at decode. Regime B (arbitrary text): the honest
  baseline is arithmetic coding under the draft, and every regime-B claim is
  reported against that bound.

## D-4 — Findings carry regime + evidence, lint-enforced
- date: 2026-08-28, status: adopted (ported unchanged from sideband)

## D-5 — Determinism dependency, narrowed to rank stability
- date: 2026-08-28, status: adopted
- Seeds stand in for determinism in the synthetic testbed. The real contract
  belongs to the lockstep runtime — and F-2 narrows it: the codec requires
  the draft's TOKEN ORDERING to be reproducible, not its logits bitwise.
  Rank-stable quantization/kernel drift is harmless by construction. This is
  the codec's ask of determinism-layer, stated precisely.

## D-6 — Rate reporting discipline
- date: 2026-08-28, status: adopted
- Every rate table includes: the format's own information bound, the
  AC-under-draft bound, a generic content coder (zlib on raw tokens), and
  raw log2(V). F-1's zlib surprise is why: a format that only beats
  strawmen is not a format.
- erratum (2026-10-11; F-16 row E18): E18: on the held-out half (P1 rows 100-199, 24780 generated tokens; dictionaries trained on rows 0-99), per archive on the full text: zstd-19 6.775 bits per generated token without a dictionary (the text carries the special-token literals E7 found, which a dictionary absorbs), 4.834 with a 4096 B dictionary (requested 4 KB), 4.439 with a 16384 B dictionary (requested 16 KB), 4.481 with a 22323 B dictionary (requested 64 KB), 4.481 with a 22323 B dictionary (requested 256 KB); amber v3 4.181 (1.050 without its 97 B fixed header). The 16 KB dictionary lowers the comparator by 34%; amber's per-archive advantage is 1.62x without it and 1.06x with it (9.728 for zstd once the dictionary's own bytes are spread over these archives). Sessions in reset mode whose rows are all held out: k=16 (5 sessions): amber v4 1.37, zstd-19 4.35 without and 3.51 with the 16 KB dictionary (multiples 3.2x and 2.6x; effect 19%); k=8 (12 sessions): amber v4 1.58, zstd-19 4.97 without and 3.70 with the 16 KB dictionary (multiples 3.1x and 2.3x; effect 25%). Concatenated full text: 3.81 without and 3.64 with the dictionary (effect 5%); by F-12's rate law the crossover moves from L 273 to 288. Content, concatenated generated text: amber v0 0.4213 against zstd-19 3.470 without and 3.322 with a dictionary trained on generated text (effect 4%): 8.2x and 7.9x. On the 22 held-out rows whose repeat-4-gram share is below one half: amber v3 5.10 against dictionary zstd 10.26 (14.38 without). Under the harvest's own definitions (special tokens skipped; repeat share over the row length) the same quantities are 6.251 and 4.446 per archive and, on 23 rows, 5.253 against 10.330, which is what its predictions were; without the literals the effects are 29% per archive, 18% and 23% for the sessions and 4% concatenated, every status unchanged. D-6's zstd rows were strawmen at the per-archive scale, strawmen at the session scale and fair at the concatenated scale; the dictionaries were trained on the other half of the same prompt families, which favours zstd.

## D-7 — Lockstep is a sibling dependency, not a copy; protocols travel, code does not
- date: 2026-08-29, status: adopted
- The determinism layer amber cites (lockstep / "determinism-layer") lives at
  ../lockstep-ultimate-repo (git, snapshot of lockstep-ultimate-repo.zip,
  sha256 41677661...) and is installed editable as `lockstep-archive`, the
  same way sideband is (D-1). Imported: rac (integer range coder, for the
  gated AC upgrade), drbg (seeded mutation sweeps), envprobe (L0 fingerprint
  once real models replace seeds), and the manifest/D-11 hardening pattern
  (ported into codec.validate_header, not imported — schemas differ).
  Experiment PROTOCOLS and test batteries (lockstep E-006/TP-4, cross-research
  XB-3) are copied with provenance lines, per cross-research T1.
- Dependency direction is MUTUAL, not one-way as v0.1.0's BLUEPRINT implied:
  lockstep has no LLM adapter (its TP-1/TP-2 are blocked on E-006), and
  amber's Phase 2 rank census is the first execution of that protocol.
  Recorded on the lockstep side as D-15.
- Known v0 gap kept explicit: the archive carries no payload digest, so
  payload-bit corruption is caught only by decode divergence or stream
  exhaustion (tests/test_hardening.py documents this). Adding original/
  payload sha256 (lockstep D-9 dual-hash) is a v1 format change.

## D-8 — Format v2: coder field, payload digest, tie escape available; gamma stays the default; value contexts are forbidden; the decoder contract is fp32-class draft replay
- date: 2026-08-30, status: adopted (F-9, F-10)
- Header gains `coder` ("gamma" | "rac1"), `tie_margin`, `tie_topm`, `max_rank`
  and `payload_sha` (D-7's open payload-digest item closed: any payload
  corruption is a typed failure before replay — mandatory once an adaptive
  coder can turn one flipped byte into a plausible wrong tail). VERSION 2;
  the gamma payload is bit-identical to v0 so F-1/F-8 remain comparable.
- Default coder stays `gamma`: rac1 gains 1% on long concatenated streams
  and loses 40% on 250-token archives (F-9); stateless beats adaptive until
  archives are thousands of tokens. rac1 is kept as the long-stream option.
- Contexts of the coder may depend ONLY on coded symbol history and
  position. Value-derived contexts (q_max, gap buckets) are worth 23-27%
  (F-9) and are forbidden: a decoder-VISIBLE quantity that is not decoder-
  STABLE desyncs an adaptive coder at every bucket-boundary crossing (F-6/F-7:
  22-41% of positions cross a 1e-3 grid even at fp32). D-2's corollary.
- The tie escape (T) stays in the format but off by default: it removes
  top-1 desyncs as designed (F-10) at 0.14-0.42 bits/token (F-9), and it does
  not reach the format's real exposure — order stability at ranks 2..64,
  which fails at 3-26% per shallow correction on a bf16 decoder (F-10).
- Decoder contract (D-5 sharpened): the draft is replayed in fp32-class
  arithmetic. Measured free across CPU/GPU/batch at every depth to 64 (0
  desyncs / 49k positions); costs 3.65x the bf16 replay time (F-7). This is
  not bitwise-determinism machinery (K-3's threat), it is a dtype pin.

## D-9 — The hf archive kind is the real format; the fp32 decoder contract is validated end-to-end; the prompt is archive content and the header is the next rate problem
- date: 2026-08-30, status: adopted (F-11)
- src/amber/real/archive.py: header kind "hf" pins {model id, snapshot,
  dtype} (L0 fingerprint), carries the prompt ids and vocab size, and adds
  `content_sha` over the archived tokens, so a desync that reaches the end is
  a typed ValueError, never a silently wrong file (lockstep D-9 dual hash).
  The pure core (symbols <-> payload, decode against a stepper) is torch-free
  and tested; the torch scorer/stepper are adapters.
- D-8's contract is now measured, not simulated: fp32 replay is byte-exact
  across device (CPU/GPU) and kernel path (teacher-forced full forward at
  encode vs incremental KV at decode), 0 desyncs / 55k positions. bf16 and
  fp16 decoders are not archive decoders (84% / 28.5% archive failure).
- erratum (2026-10-10; F-14 row E8b): E8b: confirmed: 0 failures over 54810 replayed positions (200 GPU archives with 48958 positions, 24 CPU with 5852, which F-11 prints rounded to the hundred); F-11's own results/p4_real_archive.json is read into the payload.

  (551 B/archive); a binary header still costs ~3.3 bits/token on 245-token
  archives, comparable to zstd. Next format step is header design + coding

  story must be told per archive length, not per token alone.

## D-10 — Format v3 (binary, "hfb") is the file format; the prompt is coded with the draft in the same stream; short archives are header-bound by construction
- date: 2026-08-30, status: adopted (F-12)
- src/amber/binformat.py: strict typed pack/unpack, varint ints, model pin
  (id + snapshot + 8 B fingerprint), three 8 B digests, header_sha over the
  raw header bytes; every single-byte corruption and truncation is a typed
  failure (tests/test_binformat.py sweeps every byte). JSON v2 stays for
  debugging; v3 is what gets stored.
- The prompt is content: tokens 1..P-1 are coded against the draft with the
  same {A,C,X} grammar and DECODED at replay (the decoder feeds only the
  first token). 11.3 vs 17.3 bits/token on this mix; deep-rank X handles the
  27% of prompt tokens the draft cannot see coming.
- The self-description floor (97 B) is a design fact, not an inefficiency:
  below ~250 tokens the file is mostly pins and digests. Rate claims are
  therefore stated as const/L + rate (F-12's curve), never a single
  bits/token number. Session-level archives amortise the constant; that and
  the long-horizon payload rate are the open ends (OQ-7, OQ-1).

## D-11 — Session archives (v4, kind 3) default to ctx_mode 0 (reset per turn); shared context is reserved for true multi-turn content
- date: 2026-08-30, status: adopted (F-13)
- One pin/digest set + a per-turn table amortises F-12's 97 B floor: 1.65
  bits/gen-token at 8 turns, 1.45 at 16 — 2.6-2.9x smaller than separate
  files, 3.4x under zstd-19 per session.

- ctx_mode 0 is the default: on turns generated independently (today's P1

  confines a desync to its turn. ctx_mode 1 stays in the format for true
  multi-turn sessions (target saw the history) — measure before defaulting
  to it there; do not assume the sign flips just because the story says so.
- The mode comparison itself is the D-2 lesson generalised: decoder-VISIBLE
  context is only worth using when it carries information about how the
  content was actually produced.
