## F-1 — v0 codec is byte-exact; beats the draft-AC bound where alignment is decent; loses to content-level coding in this degenerate world
- date: 2026-08-28
- regime: sideband synthetic concept-HMM v0 world, TARGET-GREEDY content, amber v0 rank codec (Elias-gamma gaps+ranks), T=20k x 2 seeds; headers excluded from rates
- source: results/a01_rate_vs_draft_quality.json, experiments/a01_rate_vs_draft_quality.py, tests/test_amber.py
- finding: decode(encode(x)) == x exactly across configs and seeds (17 tests). Rates by draft_alpha: 0.5 -> 9.29 bits/token (WORSE than raw 9.13 — the format loses below ~0.55 alignment); 0.7 -> 5.84 (beats the AC-under-draft bound 6.49 — regime-A structure the draft alone cannot see); 0.9 -> 2.17 (2.3x the AC bound, 4.2x raw); 0.97 -> 0.73 (6x the AC bound, 12.5x raw). Elias-gamma overhead vs the format's own information bound is a flat ~1.3-1.4 bits/token — the measured value of the arithmetic-coder upgrade.
- caveats: THE deciding quantity is divergence entropy vs content entropy, and this world's greedy content is degenerate — x_t is a deterministic function of a sticky 12-state chain (~0.7 bits/token intrinsic), so zlib on raw tokens scores 1.06 bits/token and beats amber everywhere except alpha=0.97. Real greedy LLM text is far higher-entropy under generic coders; the seeded-SAMPLING regime (designed, not built — A03 in BLUEPRINT) is where content entropy is high by construction and the draft-relative format's edge is structural. Do not cite these ratios outside this world; the real-pair divergence rate is OQ-1.

## F-2 — Attestation works at L1; the L0 blind spot is exactly order-preserving drift — which is also a feature
- date: 2026-08-28
- regime: amber v0 rank codec on the sideband synthetic world, T=8000; L0 = header fingerprint, L1 = target divergence-set equality; substitutions bypass L0 deliberately
- source: results/a02_attestation.json, experiments/a02_attestation.py, tests/test_amber.py
- finding: honest archive attests exactly (recomputed divergences == recorded corrections, 2346/2346); a single forged token fails L1. Silent model substitutions with L0 bypassed: draft_alpha 0.7->0.6 changes 49.3% of decoded tokens (loud); temperature 1.6->2.4 changes 0.0% and zipf_s 1.1->1.2 changes 0.0% — rank coding is INVARIANT to any order-preserving recalibration of the draft. Two consequences: (a) blind spot — L0 cannot see order-preserving drift, so strong attestation needs L1 or order-sensitive canaries; (b) feature — the determinism contract the codec actually requires is RANK STABILITY, strictly weaker than bitwise logit determinism: an order-preserving quantized draft decodes bit-exact. This narrows what the lockstep runtime must guarantee (D-5).
- caveats: order preservation under real quantization/kernels is an empirical question per model pair (OQ-2); "invariance" here is exact only because the synthetic recalibrations are exactly monotone.
- erratum (2026-10-10): see F-14, row E12

## F-3 — Rank-census instrument validated on synthetic drift: flips obey the Gaussian near-tie law, are fully attributable to near-ties, and this world has a constant top-2 gap
- date: 2026-08-29
- regime: sideband synthetic concept-HMM v0 world drafts (alpha 0.7, T=1.6, V=560), i.i.d. Gaussian LOGIT-space drift eps in {1e-3..3e-1}, T=6000 positions x 3 noise seeds; tau calibrated at the 99.9th pct of a benign draw at the same eps; instrument shakedown only, not a hardware measurement
- source: results/a03_rank_flip_synthetic.json, experiments/a03_rank_flip_synthetic.py, src/amber/rankcensus.py, tests/test_rankcensus.py
- finding: top-1 flip rate vs the pre-registered law mean_t 0.5*erfc(gap_t/2eps): eps=0.05 -> 0.0041 measured [0.0030, 0.0052 across seeds] vs 0.0042 predicted; eps=0.1 -> 0.0957 [0.0932, 0.0973] vs 0.0940; eps=0.2 -> 0.278 vs 0.255 and eps=0.3 -> 0.396 vs 0.330 (law is a stated lower bound: it ignores rank-3+ intruders, which appear once eps ~ gap). flips_beyond_2tau = 0 at every eps and seed — every flip is attributable to a near-tie by the calibrated tolerance, i.e. the near-tie-vs-bug discriminator does not false-alarm on genuine i.i.d. drift. Dispersion index 0.92 at the 0.4% flip rate (Poisson-scattered, as i.i.d. drift must be), falling below 1 only as windows saturate. Instrument tests include a RED-proof (deliberate one-position misalignment fires wide-gap flips) and set-vs-order distinction.
- caveats: this world's draft has a CONSTANT reference top-2 logit gap of 0.1862 at every position (all quantiles identical) — a structural artifact of the tempered-mixture draft, so nothing flips below eps ~ 0.03 and the flip curve is a single step, not a spread. Real drafts have a gap DISTRIBUTION with mass near zero, which is where the hardware question (OQ-2) actually lives; the constant gap is why the law fits so cleanly here. Burstiness cannot be tested in this world (drift is i.i.d. by construction); E-006's bursty-corrections stop condition is a GPU-only question.

## F-4 — The seeded mutation sweep found silent header corruption: a one-bit flip in the length digits decoded 'successfully' to a longer sequence; fixed by sealing the header
- date: 2026-08-29
- regime: amber v0.1.0 archive framing (JSON header + Elias-gamma payload), 400 DRBG-seeded single-byte mutations + exhaustive 1-bit flips over every header byte, T=300 synthetic archive
- source: tests/test_hardening.py, src/amber/codec.py (validate_header, header_digest)
- finding: v0.1.0's L0 fingerprint covered only (cfg, path_seed, draft_seed); length, n_corrections and payload_bits were unauthenticated, so an ASCII bit flip turning "300" into "310" parsed, validated, replayed and returned 310 tokens with no error — the exact silent-success class lockstep F-3 found in its container. Also present pre-fix: bare KeyError/TypeError/JSONDecodeError on malformed headers, an unbounded declared length (decompression bomb via replay work), duplicate JSON keys resolved last-wins, NaN accepted. Post-fix: strict typed schema (exact field set, int-not-bool, ranges, 16-hex digests), header_sha over all fields, declared-length ceiling (default 2^24, caller-tunable) checked BEFORE any replay, duplicate-key and non-finite rejection; 400-mutation sweep + exhaustive header-bit flips leak no builtin exception and no header mutation decodes to different tokens. Format change: header gains header_sha (v0.2 archives; v0.1.0 archives are rejected as missing the field).
- caveats: no key, so this is damage detection, not forgery resistance — a resealed forgery is only caught by the L0 model pin and the length ceiling (tested). The payload still carries no digest: payload-bit corruption is caught only by decode divergence or stream exhaustion (documented gap, D-7); a dual-hash (original + payload sha256, lockstep D-9) is the v1 fix and would also give L0 attestation a token-level check without the target.
- erratum (2026-10-10): see F-14, row E11

## F-5 — Phase 2 rank census (TinyLlama-1.1B, one 3080 Ti box): fp32 cross-device rank order is exactly stable; bf16 flips 1.0% of top-1s, every one a near-tie; run-to-run is bit-identical; the pre-registered band (c) fired on bf16 batch dependence, which the investigation attributes to kernel selection (N2), not a bug
- date: 2026-08-29
- regime: TinyLlama/TinyLlama-1.1B-Chat-v1.0 (Llama arch, V=32000; snapshot fe8a4ea1) teacher-forced on 96x512 windows of tokenizer-lab mix_docs50_wiki50 (49,152 positions, no padding); top-256 dumps, census at k=64; reference CPU fp32; RTX 3080 Ti, torch 2.6.0+cu124, transformers 4.57.3, cudnn default (deterministic_algorithms off); envprobe 2d2a2e0c; bands pre-registered in experiments/P2_PROTOCOL.md. NOT Llama-3.2-1B (gated repo not authorized on this box); same command re-runs it when access lands.
- source: results/p2_rank_census.json, experiments/p2_rank_census.py, experiments/P2_PROTOCOL.md, src/amber/real/capture.py, src/amber/rankcensus.py
- finding: vs CPU fp32 — cuda_fp32: 0 top-1 flips / 49,152 (top-64 SET flip 1.4e-4, p99 |dlogit| 1.5e-5, max 1.3e-4); cuda_fp16: 0.114% (56 flips; gap median 0.0044, max 0.041; 0 beyond 2tau=0.142); cuda_bf16: 1.015% (499; gap median 0.028, max 0.23; 0 beyond 2tau=0.93); int8: 4.04% (0 beyond 2tau=5.0); nf4: 10.2% (3 beyond 2tau=12.3, gap max 7.06 — quantization changed the MODEL, not drift). Halves agree within ~1.7x for every arm (bf16 0.74%/1.29%). Dispersion ~1.1-1.4 for fp16/bf16 (Poisson-scattered), 2.1 int8, 4.1 nf4 (bursty; protocol rule >3 triggered for nf4 only). Determinism checks: CPU run-to-run and GPU bf16 run-to-run BIT-IDENTICAL; fp32 batch 1 vs 8: 0 flips, max |dlogit| 1.9e-4 (not bit-identical); bf16 batch 1 vs 8: 430 flips (0.87%), 0 beyond bf16's own 2tau, gap max 0.375, flat across in-batch row index (0.30-0.34) and position quarters — the signature of batch-dependent kernel selection (lockstep taxonomy N2 / PA-10), not of a mask or gather bug (a bug would localize to rows/positions and would show in fp32). The pre-registered rule 'any determinism-check flip => band (c)' therefore fired as written; the post-hoc block (labeled as such in the census output) resolves it, and the substantive verdict is band (b): rank stability across DTYPE is not free — a bf16 draft-only decoder would silently diverge at ~1% of positions — but every flip is a near-tie, so a gap-thresholded escape symbol is viable and its cost is P(gap < threshold) under the reference: 6.7% of positions at 0.142 (fp16's 2tau), 19.0% at 0.465, 32.6% at 0.93 (bf16's 2tau). Within fp32 (CPU vs GPU, batch 1 vs 8), the D-5 contract is met exactly at zero format cost. Throughput (measured): CPU fp32 ~280 pos/s, GPU fp32 ~6k, fp16/bf16 ~12-19k, int8 3.5k, nf4 7k.
- caveats: one model, one box, one corpus, one GPU architecture; cross-GPU-architecture drift (A100 vs H100, PA-7) is unmeasured; 'bit-identical run-to-run' is a property of this torch/cudnn build with autotune defaults and must be re-checked on upgrade (lockstep N3); TinyLlama's gap distribution (median 1.88, 1% below 0.022) is the quantity every escape-cost number above depends on and will differ for Llama-3.2-1B. The band-(c)-by-the-letter outcome is a protocol lesson recorded in P2_PROTOCOL.md: batch pairs should be judged at the dtype's own tau, not expected bit-identical.
- erratum (2026-10-11): see F-16, row E17

## F-6 — Same dumps read as lockstep's E-006: fp32 cross-device drift crosses a 1e-3 logit grid at 22% of positions (law k*eps/delta holds), bf16/fp16 at 100% — rank stability is orders of magnitude cheaper than grid stability
- date: 2026-08-29
- regime: as F-5; crossing = any CPU-top-64 token changes floor(logit/delta) or leaves the GPU arm's top-64; delta in {1e-2, 1e-3, 1e-4}, k=64 (lockstep D-13's proposed profile)
- source: results/p2_e006_grid_crossing.json, results/p2_rank_census.json
- finding: CPU fp32 vs GPU fp32: eps p50 3e-6, p99 1.5e-5, max 1.3e-4 (absolute, on logits of magnitude ~10); positions with >=1 crossing: 2.6% at delta=1e-2, 21.9% at delta=1e-3, 90.8% at delta=1e-4. Lockstep F-7's law k*eps/delta with the MEASURED median eps predicts 1.9% / 19% / 190%(saturates) — it holds on real hardware at the delta where it is not saturated. bf16 and fp16 vs CPU fp32: 100% of positions cross at every delta (eps p50 0.024 / 0.0031). Contrast with F-5: the RANK order of the same top-64 flipped its top-1 zero times at fp32, 0.11% at fp16, 1.0% at bf16. For a byte-exact archive, an ORDER contract (amber D-5) costs 0% corrections at fp32 where a grid contract at lockstep's D-13 defaults (delta 1e-3, k 64) would cost a correction at 22% of positions; even delta=1e-2 costs 2.6%.
- caveats: this is the fp32 cross-DEVICE number on one CPU/GPU pair, not cross-architecture; lockstep's E-006 asks for >=2 GPU architectures and burstiness of crossings (not computed here). The grid result does not say lockstep's design is wrong for its own goal (a coder that needs exact PROBABILITIES) — it says amber's weaker contract is the right one for a codec that only needs ranks, which is exactly the D-5/D-15 split.

## F-8 — Phase 1 (OQ-1) on the real Llama-3.2 pair: 6.8% greedy divergence; amber v0 codes target-generated text at 0.47 bits/token — 7.6x below zstd-19 — and ties AC-under-draft exactly; the pre-registered bands had a dead zone there; target generate-vs-forward self-consistency is 99.67%, below the protocol's 99.9% line

## F-9 — Coder upgrade (lockstep rac, order-only contexts) gains 1% over Elias-gamma on the real stream and PASSES the pre-registered rac-vs-AC band on held-out — but the sign of amber-vs-AC flips between prompt halves, the adaptive coder LOSES on 250-token archives, and the only large lever (value contexts, -23%) is the unsafe one; the tie escape costs 0.14-0.42 bits/token
- date: 2026-08-30
- regime: P1 stream (F-8: Llama-3.2-3B base greedy -> 1B base draft ranks, bf16, 200 sideband prompts x <=256 tokens); tuning rows 0-99 (24,178 tokens, divergence 7.49%), held-out rows 100-199 (24,780 tokens, 6.10%); rates are real payload bytes x 8 per token, headers excluded; coder = lockstep.rac (integer WNC) with amber's small-alphabet adaptive models; hyperparameters (increment 64, rescale 4096 — the most adaptive corner of the grid) chosen on the tuning split only; P3_PROTOCOL.md frozen before the coder saw the data

- finding: Held-out, concatenated stream (bits/token): gamma v0 0.4213, rac1 0.4171, AC-under-draft 0.4380, zstd-19 3.470, raw 16.97. The pre-registered band fires PASS (per-prompt bootstrap of rac1 - AC: CI95 [-0.040, -0.001]). Tuning half: gamma 0.5274, rac1 0.5205, AC 0.5075 (CI [-0.009, +0.036]) — AC wins there. So amber-vs-AC is +/-0.02 bits/token with a split-dependent SIGN, and F-8's 'tie' was the average of two opposite-sign halves; the coder upgrade moves amber by only 0.004-0.007 bits/token (1%), because the order-only contexts (previous flag, position bucket) carry almost nothing Elias-gamma's gap coding does not already exploit. All 17 variants x 2 modes x 2 splits passed the symbol-level roundtrip stop condition.
- caveats: PASS is by the letter of the protocol; the protocol's single-split CI was too weak against split heterogeneity (a sign-agreement-across-halves criterion would have returned TIE) — recorded as a protocol note, not reinterpreted. Tuning grid's best point is at the grid edge (faster adaptation may gain a little more; not chased). One pair, one prompt set, 256-token horizon. The synthetic world (F-1) turns out to have NO shallow corrections — every wrong draft there is wrong by hundreds of ranks (tests/test_rac_codec.py documents it) — so F-1's '~1.4 bits recoverable by AC' was a property of that world, not a forecast.

## F-10 — The near-tie escape does exactly what it was built for (top-1 desyncs -> 0 at theta >= 2*tau) and it is not enough: on the P2 dumps a bf16 decoder mis-resolves 3% of rank-2 and 9-26% of rank-3..8 corrections written by an fp32 (or batch-1 bf16) encoder, which on P1's rank distribution is one desync per ~170 target-generated tokens; only an fp32-class decoder is clean (0 desyncs / 49k positions / all ranks to 64)
- date: 2026-08-30
- regime: results/p2_llama32 dumps (Llama-3.2-1B-Instruct, top-256 per arm, 49,056 teacher-forced positions of tokenizer-lab mix_docs50_wiki50 text — real text, NOT target-generated: true-token rank median 1 / p90 80 / p99 257, 10.9% beyond R=64 and coded X); symbol stream built under the encoder arm (cpu_fp32; cuda_bf16_b1 for the serving case) with the v2 classifier, resolved under each decoder arm; counts of positions whose resolved token differs; no coder state involved (the coder's contexts are value-free, so a desync is a wrong token, never a lost stream)
- source: results/p2b_escape_robustness.json, experiments/p2b_escape_robustness.py, experiments/P3_PROTOCOL.md, results/p2b.log, results/p2_llama32_rank_census.json
- finding: (1) Escape works as specified: A-desyncs fp32->fp16 25 -> 0 at theta 0.142; fp32->bf16 159 -> 2 at 0.142 -> 0 at 0.465; bf16_b1->bf16_b8 115 -> 0 at 0.465; every A-desync at theta=0 has encoder gap below the pair budget 2(tau_enc+tau_dec) (XB-3 check: no wide-gap flip, no pipeline bug). (2) fp32 -> cuda fp32: 1 desync at theta=0 (gap 1.3e-5), ZERO of any class at theta >= 0.142, across all ranks to 64 and both C codings.
